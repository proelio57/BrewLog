# Decent DE1 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** BrewLog connects to a Decent DE1 over Bluetooth, records pressure, flow and temperature of every shot, follows the shot (timer starts/stops with the machine) and can wake, sleep, start and stop it — like it does for GaggiMate.

**Architecture:** The live machine state type `GaggiMateStatus` is renamed `MachineStatus` (it already is the generic state). A pure `DecentProtocol` decodes the DE1's BLE packets into `MachineStatus` and encodes commands; a `DecentConnection` (CoreBluetooth) feeds it into `MachineManager`, which gains `MachineKind.decent`. UI parts that are GaggiMate-only (profiles, temperature nudge, machine scale) are gated by `MachineManager.capabilities`.

**Tech Stack:** Swift 5 mode, SwiftUI, CoreBluetooth, iOS 17, XCTest (+ `scripts/test-pure-swift.sh` for the protocol).

**Spec:** User request 2026-11-05 ("decent espresso Maschinen Support einbauen", after the GaggiMate profile work). Protocol: decentespresso/de1app (`de1plus/binary.tcl`, `de1plus/bluetooth.tcl`), cross-checked with nicpottier/decent (Go) `types` package.

## Global Constraints

- BLE service `0000A000-0000-1000-8000-00805F9B34FB`; characteristics `0000A00x-0000-1000-8000-00805F9B34FB`: `A002` RequestedState (write, 1 byte), `A00D` ShotSample (notify), `A00E` StateInfo (read + notify). Advertised name starts with `DE1`.
- All multi-byte values big-endian. ShotSample (19 bytes): `SampleTime U16` (half-cycles), `GroupPressure U16P12` (/4096 bar), `GroupFlow U16P12` (/4096 ml/s), `MixTemp U16P8` (/256 °C), `HeadTemp U24P16` (/65536 °C), `SetMixTemp U16P8`, `SetHeadTemp U16P8`, `SetGroupPressure U8P4` (/16), `SetGroupFlow U8P4` (/16), `FrameNumber U8`, `SteamTemp U8`.
- StateInfo (2 bytes): state, substate. States: 0 sleep, 1 going_to_sleep, 2 idle, 3 busy, 4 espresso, 5 steam, 6 hot_water, 7 short_cal, 8 self_test, 9 long_cal, 10 descale, 11 fatal_error, 12 init, 13 no_request, 14 skip_to_next, 15 hot_water_rinse, 16 steam_rinse, 17 refill, 18 clean, 19 in_boot_loader, 20 air_purge, 21 sched_idle. Substates: 0 no_state, 1 heat_water_tank, 2 heat_water_heater, 3 stabilize_mix_temp, 4 pre_infuse, 5 pour, 6 flush, 7 steaming, … ≥ 200 errors.
- A shot is running while state == 4 and substate ∈ {4 pre_infuse, 5 pour}. `processKind` = `"infusion"` for 4, `"brew"` for 5 (same strings as GaggiMate so `BrewSession` needs no change).
- Commands: wake = RequestedState 2 (idle), sleep = 0, start shot = 4, stop = 2 (idle). A DE1 with a group-head controller (GHC) refuses app-started shots: BrewLog then shows "Start the shot on the machine." and keeps following it.
- `MachineMode` mapping: standby → 0, brew → 2, steam → 5, water → 6.
- No profile upload in this plan (DE1 frame format is a separate piece of work); DE1 has no scale, the BOOKOO scale stays the weight source. The DE1 measures pressure itself, so `readsPressure` is true and the BOOKOO pressure sensor is not offered (existing rule).
- Bluetooth permission text exists already (scale); no new Info.plist keys. Privacy rules of `docs/ai-parity-guide.md` §1 hold (no network).
- Verification: protocol tests on Linux (`scripts/test-pure-swift.sh`), app via iOS CI on the PR. Hardware behaviour is checked by the user with the run list in Task 3.

## Review Focus

- A ShotSample shorter than 19 bytes or a StateInfo shorter than 2 (partial notification): ignored, previous status kept (test `testShortPacketsAreIgnored`).
- Error substates (≥ 200) or state 11 fatal_error: status shows `systemState = "error"` with a readable message, and a running shot ends (test `testErrorStateEndsShot`).
- Flush / hot water / steam (states 5, 6, 15, 16): never counted as a shot (test `testFlushIsNotAShot`).
- The DE1 drops the connection mid-shot: `onShot(false)` fires once and the session finishes via the existing path (same as GaggiMate's `connectionLost`; checked in `DecentConnection` by calling the shared `connectionLost` handler, run list item).
- A second DE1 or the BOOKOO in range while scanning: only devices advertising service `A000` are listed, the remembered one reconnects by identifier (run list item).

### Task 2: DecentProtocol (pure)

**Files:**
- Create: `BrewLog/Machine/DecentProtocol.swift`
- Test: `BrewLogTests/DecentProtocolTests.swift`

**Interfaces:**
- Produces:
  ```swift
  enum DecentProtocol {
      static let service: String            // "0000A000-0000-1000-8000-00805F9B34FB"
      static let requestedState, shotSample, stateInfo: String   // A002, A00D, A00E full UUIDs
      struct Sample: Equatable { var pressure, flow, mixTemp, headTemp, targetMixTemp, targetHeadTemp, targetPressure, targetFlow: Double; var frame: Int }
      static func sample(_ data: Data) -> Sample?               // nil if count < 19
      static func state(_ data: Data) -> (state: UInt8, substate: UInt8)?   // nil if count < 2
      static func apply(state: UInt8, substate: UInt8, to status: inout MachineStatus)
      static func apply(_ sample: Sample, to status: inout MachineStatus)
      static func command(for mode: MachineMode) -> Data
      static let startShot: Data, stopShot: Data                 // [4], [2]
  }
  ```
  `apply(state:)` sets `mode` (0→standby 0, 2→brew 1, 4→brew 1, 5→steam 2, 6/15→water 3), `processActive`, `processKind`, `processLabel` ("Pre-infusion"/"Extraction"), `processIsUtility` (true for 6, 15, 16, 18, 10), `systemState`/`systemMessage` for 11 and substate ≥ 200. `apply(sample)` sets `pressure`, `flow`, `temperature` (= headTemp), `targetTemperature` (= targetHeadTemp, nil when 0), `targetPressure` (nil when 0), `hasPressure = true`.

### Task 3: Connect the DE1 and use it for shots

**Files:**
- Create: `BrewLog/Machine/DecentConnection.swift`, `BrewLog/Views/Gear/DecentConnectSheet.swift`
- Modify: `BrewLog/Machine/MachineManager.swift`, `BrewLog/App/Settings.swift` (key `machineDecentID`), `BrewLog/Views/Gear/GearViews.swift` (machine section), `docs/data-formats.md` (new "Decent DE1" section with the constraints above), `docs/ai-parity-guide.md` (Espresso Machine row), `README.md` (feature list line)

**Interfaces:**
- Consumes: `DecentProtocol` (Task 2), `MachineCapabilities` (Task 1).
- Produces:
  ```swift
  final class DecentConnection: NSObject {   // owns its CBCentralManager
      var onStatus: ((MachineStatus, _ telemetry: Bool) -> Void)?
      var onDisconnect: (() -> Void)?
      private(set) var discovered: [DiscoveredDevice]          // reuse the scale's DiscoveredDevice type if it fits, else id/name/rssi
      func startScan(); func stopScan()
      func connect(_ id: UUID)                                  // remembers id in SettingsKey.machineDecentID
      func reconnectRemembered(); func disconnect(forget: Bool)
      func write(_ command: Data)                               // to A002, .withResponse
  }
  ```
  `MachineKind.decent` (displayName "Decent DE1"). `MachineManager.restart()` for `.decent` calls `decent.reconnectRemembered()`; `state` = `.connecting` until StateInfo arrives, `.connected` after, `.unreachable` on disconnect (retry after 5 s like GaggiMate). `setMode`, `startShot`, `stopShot` write the `DecentProtocol` commands; `startShot` shows `notice = "Start the shot on the machine."` if no state 4 arrives within 2 s.
